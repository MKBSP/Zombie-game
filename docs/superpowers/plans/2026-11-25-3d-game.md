# Plan: the 3D game: menu, test museum, HUD, then online

## Context
The 3D work (the first-person shooter, the zombie commander, survivors, crates and
street lights on the small city, `scenes/test/camera_test_v6_small_city.tscn`)
only runs with F6 from the editor. The main menu still starts the old 2D game.

Mads wants:
- the 3D game to become the real game, launched from the menu;
- the 2D game retired;
- an in-game ESC menu to switch between shooter and commander and to turn on cheats;
- a test museum (zoo, museum stations, gym, lighting lab, facade wall) opened
  from the menu, for checking assets, systems and the look;
- the HUD and style from the approved mockup (v4, https://claude.ai/artifact/5hAuRpAShsPkGvKjN127Mc);
- builds a tester can run on their own laptop;
- online 3D multiplayer last.

Order agreed: **1 game shell → 2 museum step 1 → 3 museum stations + gym →
4 HUD → 5 online (S10) → 6 delete 2D (S11)**. Each phase ends playable and
push-ready, with a suggested commit message.

**How we work.** House rules say game-file edits go through the godot-ai MCP. It
is down right now (connection refused). So either Mads opens the editor with the
plugin running, or Mads closes the editor while files are edited directly
(memory: stale editor tabs overwrite edits). Visual checks run in the scratchpad
copy of the repo with a windowed `--script` harness, never headless in the live
repo. No commits unless asked, and never push. Step 0: save this plan as
`docs/superpowers/plans/2026-11-25-3d-game.md` and mark track 0 approved in
`docs/BACKLOG.md`.

## Phase 1: game shell (menu, ESC menu, style, tester builds)

### 1.1 Share one rig between the city and the museum
- New `scenes/game/rig.tscn` (root `Rig`, Node3D) holding today's v6 nodes:
  `TestPlayer`, `CameraRig`/`Camera3D`/`Viewmodel`, `DebugHUD`, `TuningHUD`,
  `Commander`, plus the new `GameMenu`. Copy their export values from the v6
  .tscn (view_mode=3, flashlight settings, and so on).
- These are already export NodePaths. In `rig.tscn`, set the ones that point
  outside the rig to `../../City`, `../../StreetLights` and
  `../../WorldEnvironment`: `commander.gd:42-43` and `test_hud.gd:13`. The ones
  inside the rig stay as they are.
- Move the v6 scene to `scenes/game/city.tscn` (keeps its uid). Its tree becomes
  `City`, `WorldEnvironment`, `StreetLights` and `Rig`.
- `test_fp_aim.gd` and `test_commander_map.gd` find the player with a recursive
  `find_child`, so only their scene path changes.
- Scripts stay in `scripts/test/`. Renaming them is cosmetic, so it's skipped.
- `commander.gd` gets three exports, `spawn_horde`, `spawn_npcs` and
  `spawn_crates` (default true). `spawn_point` is already an export. The museum
  turns the spawns off but keeps the navmesh bake (`_bake_nav` 122-145).

### 1.2 Main menu starts the 3D game
In `scenes/ui/main_menu.gd`:
- The title rows become **PLAY**, **TEST MUSEUM**, **SETTINGS** and **QUIT**.
- PLAY goes to the existing RolePanel. The role cards set `GameState.role` and
  change scene to `scenes/game/city.tscn` (`:110-112`) instead of `world.tscn`.
- **MULTIPLAYER is hidden** until phase 5. The `--server`, `--host` and
  `--join` paths are untouched, so the Railway server and `run_local_mp`
  keep running the 2D game.
- In `commander.gd` `_ready`, `start_active` is set from
  `GameState.role == ZOMBIE`. With F6 it still defaults to shooter.

### 1.3 In-game ESC menu
New `scenes/ui/game_menu.gd`. It's built in code with the `MenuWidgets` builders,
like `SettingsMenu`, with `PROCESS_MODE_ALWAYS`. It pauses the tree, following
the 2D `pause_menu.gd` pattern.

Items:
- Resume.
- **Play as shooter / Play as zombie commander**, which calls
  `commander.set_active()` (`commander.gd:196`).
- **Cheats: all weapons + unlimited ammo** (toggle).
- Settings (`SettingsMenu` in overlay mode).
- Restart.
- Quit to menu.
- In the museum only, a **Go to** list of areas.

Changes elsewhere:
- **ESC in shooter mode** opens the menu, replacing the mouse-free in
  `test_player.gd:363-366`.
- **ESC in commander mode** first clears a pending order or selection
  (`_escape()`, `commander.gd:442`). Only if there is nothing to clear does it
  open the menu.
- The commander caches every CanvasLayer it hides (`commander.gd:202-205`).
  Skip nodes in a `"keep_visible"` group so the menu isn't hidden with the
  shooter HUD.
- **Cheat refactor** in `viewmodel.gd`:
  - Move the F9 body (`:649-655`) into `set_cheat(on)`.
  - While cheat is on, skip `a.mag -= 1` (`:1101`), so ammo really is unlimited.
  - F9 and TAB stay as debug shortcuts.
  - The menu toggle works in every build, so testers have it.
  - Hiding it for public release goes on the backlog.

### 1.4 Style v2 (menus now, HUD in phase 4)
- Swap the tokens in `scripts/ui_style.gd` to the mockup's v2 palette:
  - abyss `#080603`, bunker `#0e0a06`, trench `#1c1409`
  - ash `#c4b48a`, moss `#7a6448`, dim `#4a3820`

  - hem `#c0141a` (damage only)
  - amber `#d4780a`, cyan `#00b4c8`, lure `#c8920a`
  - borders: amber hairline at 32% and 16%
- Type: Share Tech Mono for labels and numbers, Rajdhani for sentences, Special
  Elite for titles only. Corners are cut or sharp, never round; borders are 1 px.
- `UITheme` builds from these tokens, so every menu restyles.
- Rewrite `docs/design_system.md` to match.
- The settings screen's CONTROLS list (`settings_menu.gd:16-34`) shows 2D keys.
  Replace it with the 3D shooter and commander keys.

### 1.5 Tester builds
- Add **macOS** and **Windows** presets to `export_presets.cfg`. Godot 4.6.3
  templates are installed. Builds go to `build/`, which gets gitignored.
- Remove the Web preset: browsers can't run Forward+.
- Check that the exported build boots clean with the `_mcp_game_helper`
  autoload. If it errors, exclude `addons/godot_ai` from the export.
- Add a "Tester builds" section to `DEPLOY.md`: how to export, how to zip, and
  how a tester opens an unsigned app (Mac: right-click → Open; Windows: More

### 1.6 Docs

- CLAUDE.md fast facts: the main scene is the loading screen, the renderer is

- ARCHITECTURE.md (rig, game menu), CHANGELOG, BACKLOG.

## Phase 2: test museum, step 1 (zoo, lighting lab, facade wall) + stand-in props

### 2.1 Stand-in props from Poly Pizza (Claude picks them; style comes later)
Download into `assets/props/<category>/` and add credits to CREDITS.md under a
new `## Props`. All CC0 unless marked.

- **Packs:**
  - Quaternius *Cars Bundle* (car ×2, sports car, police car, taxi, SUV).
  - Quaternius *Post Apocalypse Pack*, props only (cinder block, trash bags,
    traffic barriers, cones, containers, barrel, pallets). Skip its five CC-BY
    characters.
  - Quaternius *Stylized Nature MegaKit* (trees, dead trees, grass, tall grass,
    bushes).
- **Singles:**
  - Quaternius: pickup truck, delivery truck, dumpster, trash can.
  - Kay Lousberg: car hatchback.
  - Kenney: construction barrier.
  - **Bus** and **shopping cart**: Poly by Google, **CC-BY 3.0**, credit line
    required. No CC0 option exists for either.
- Scale each model to real metres through its `.glb.import` root scale, so no
  code is needed.
- New `scripts/3d/prop_3d.gd` (`class_name Prop3D`, `@tool`): exports `model`,
  `state` (INTACT / BURNT / BURNING) and `surface`.
  - It builds a box `StaticBody3D` from the model's bounding box, on layer 1 so
    it's cover and blocks the navmesh.
  - It sets the `surface` meta used by `ImpactFx.surface_of` (`impact_fx.gd:21`).
  - BURNT applies a charred `material_override`. BURNING is BURNT plus a `Fire3D`.
  - It can be placed by hand in the editor or spawned by the zoo.
- New `scripts/3d/fire_3d.gd` (`Fire3D`): flame and smoke `GPUParticles3D`, plus
  an `OmniLight3D` driven by the existing `scripts/test/flicker_light.gd`.
  The `size` export scales all three.

### 2.2 Museum scene: `scenes/museum/museum.tscn` + `scripts/museum/museum.gd`
- Built in code at `_ready`, so new assets don't need scene edits.
- An open-air hall with no roof, because NPC and crate placement rejects roofed
  spots (`npc_3d.gd:283`).
- The floor is a StaticBody3D with a new `shader/grid_floor.gdshader` (1 m
  lines, 5 m bold, world-aligned) and Label3D metre numbers.
- Walls are named `Building*`, because zombie line of sight, NPC cover and fog
  key off that prefix.
- The `City` node holds the hall geometry, plus `Rig`. The commander bakes the
  navmesh, with horde, NPC and crate spawns off.
- **Areas**, each with Label3D signs, reached with the ESC menu's **Go to** list.
  Number keys are taken by weapons.
  1. **Zoo.** One row per folder.
     - Characters: adventurer, business_man, hoodie, man, and the zombie in each
       variant STANDARD/FAST/FAT/MASTER. These are bodies only
       (`zombie_body.gd` with a variant, idle animation), with no AI, on slow
       turntables.
     - Weapons: world models from `assets/weapons/*.glb` and the first-person
       arms.
     - Loot: a crate closed and one open (`loot_crate.gd`, `open()`), and every
       `Pickup3D.drop` kind.
     - Street lights: one in every `StreetLight.State`.
     - Props: every `assets/props/**` model, with vehicles and the dumpster shown
       intact, burnt and burning.
     - Rows are filled with `ResourceLoader.list_directory()` (works in exported
       builds), so a dropped-in .glb shows up with its file name as the sign.
  2. **Lighting lab.** A museum-only panel, toggled with **L**, controls the
     whole museum:
     - Sun on/off, strength, height and direction (time of day).
     - Ambient/moonlight strength and colour, fog density, exposure.
     - Presets: **Game night** (copies the v6 environment and moon from
       `test_hud.gd:59-66`), **Torch only**, **Daylight**.
     - Buttons add a flickering lamp, a fire, a street light or a lookdev stand.
       **G** grabs the light or stand you look at, carries it, and drops it.
       G is free in shooter mode.
     - **Lookdev stand:** an 18% grey ball, a chrome ball and a 24-patch colour
       chart (boxes with the standard sRGB values).
  3. **Facade wall.** Hand-built `ArrayMesh` quads using
     `shader/city_building.gdshader`:
     - `UV` = metres, `UV2` = (length, height),
       `COLOR` = (seed, seed2, 0.5, 1); seed2 < 0.62 is brick, otherwise stucco.
     - All five `side` values (back, alley, street, shop street, party wall)
       × brick/stucco × 3 heights (7, 13 and 19 m) × 2 seeds, plus a roof sample.
     - The lab panel gets the shader's sliders (`lit_windows`, `window_glow`,
       `shop_glow`, `sign_glow`, `shop_chance`), live.
  4. **Survivors and crates.**
     - Three survivors stand in the open: walk in to recruit, E to hand over a
       gun.
     - Three crates sit next to them, and a **Reset crates** button respawns
       them.
- Main menu: **TEST MUSEUM** opens `scenes/museum/museum.tscn`.

## Phase 3: museum stations + gym
Each station has a sign saying what to try, and a reset post (E).
- **Body parts:** a dummy zombie with a new `dummy` flag on `zombie_3d.gd`: no
  AI, still takes `take_part_hit` (`:468`). Shoot parts off and watch it crawl.
- **Zombie pen:** a fenced yard with three live zombies. Watch them chase,
  search and lose you.
- **Surface wall:** panels tagged ground, wall, metal, glass, wood and flesh, to
  check holes, dust and sparks.
- **Survivors:** recruit, give a gun, and watch them shoot at the pen.
- **Commander:** a sign explaining that switching role (ESC menu) shows the fog
  of war over the museum, with a few zombies to order around.
- **Gym:**
  - A firing range with boards at 5, 10, 20 and 40 m.
  - Doorways 0.8, 0.9, 1.2 and 2 m wide.
  - Stairs with 0.15, 0.2, 0.25, 0.3 and 0.4 m steps.
  - Slopes of 10, 20, 30, 40 and 50°.
  - A 50 m walk and sprint track marked every 5 m.

## Phase 4: HUD from mockup v4
Two registers: a quiet shooter HUD and a boxed commander HUD.

- **Shooter:** new `scripts/ui/hud_shooter.gd` replaces `viewmodel._build_hud()`
  (`:529-610`) and the minimap in `test_hud.gd`.
  - Health and hands are always shown.
  - A small row of carried weapons.
  - Ammo, mag and reserve.
  - Prompts under the crosshair; alerts on the left.
  - A minimap at the top right showing streets, you and your followers,
    **never zombies**. This fixes the leak.
- **Commander:** new `scripts/ui/hud_commander.gd` replaces
  `commander._build_hud()` (`:604-673`). It's the AoE2 bottom panel with three
  fixed slots:
  - **Commands:** stance and orders.
  - **Selection:** 16 cards (body diagram, HP, state, map square), or one
    zombie's details.
  - **Map:** the whole city, black where unexplored, with an A–F / 1–4 grid.
    This reworks `commander_map.gd`.
  - Above the panel: control groups and an event feed on the left that uses map
    squares.
  - Help moves behind F1.
- The H tuning panel is **hidden by default** (`test_hud.gd:126-166`).
- **Calls made on the mockup's open questions:**
  - The HUD shows what the game has today: one gun, with the torch in the other
    hand.
  - Dual-wielding and the one-/two-hand bat grip aren't in the game. They go to
    the backlog, and the HUD's two hand slots are ready for them.
  - The two registers stay as in the mockup, and so does the shooter minimap.
